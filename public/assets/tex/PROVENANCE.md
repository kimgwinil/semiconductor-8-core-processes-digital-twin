## 2. 프롬프트 원문 전체

**생성 프롬프트 없음 — 절차적 생성이다.**

생성형 모델을 쓰지 않은 이유:
1. **라이선스 리스크가 0이다.** 외부 소재·모델 출력물이 개입하지 않으므로 E-001 클린룸 논리에 가장 안전하다.
2. **재현 가능하다.** 시드가 `20260820` 으로 고정돼 있다(프롬프트 표준 §5 시드 기록 의무 충족).
   🔴 **2026-08-20 정정(V6 F-7) — 「완전」이라는 말을 뺐다.** 시드가 보장하는 것은 **픽셀**이고, **바이트 동일성은 인코더 버전에 의존**한다. 실측 환경을 명기한다:
   **cwebp 1.6.0 / libsharpyuv 0.4.2 · Python 3.9.6 · numpy 1.22.0 · Pillow 11.3.0 · macOS arm64.**
   이 환경에서 V6 가 백업→재생성→SHA-256 대조로 **5종 전량 바이트 동일**을 실증했다. 다른 cwebp 버전에서는 바이트가 달라질 수 있다.
3. **타일러블을 보장할 수 있다.** 생성 모델은 이음매 없는 타일을 안정적으로 만들지 못한다. 절차적 생성은 wrap-around 격자에서 노이즈를 만들어 **구조적으로** 이음매가 없다.
4. **알베도만 만들 수 있다.** 생성 모델은 요청하지 않아도 명암·하이라이트를 굽는다. DEV 규격이 금지한 것이다.

## 6. 자체 검증 결과 (2026-08-20 · 🔴 **재측정본**)

> 🔴 **이 절은 통째로 다시 썼다. 종전 표는 납품물을 측정한 적이 없다** — 독립 검수 **V6 · F-1** 이 적발했다.
> 종전 `seam_error()` 는 **압축 전 numpy 배열**만 쟀고 내부 기준도 0열↔1열 **한 쌍**뿐이었다.
> 절차적 생성 자체는 진짜 타일러블이었으나(압축 전 이음매/내부 비 ≤1.68) **cwebp lossy q88 이 이음매를 만들어**

> **검사는 납품물을 재야 한다.** 도구를 고치고 인코딩을 바꾼 뒤의 실측이 아래다.

**바뀐 것 3가지**
1. 🔴 **검사 대상** — 압축 전 배열 → **납품 `.webp` 를 다시 디코드해서** 잰다(`decode()` 신설)
2. 🔴 **내부 기준** — 0열↔1열 한 쌍 → **내부 인접 쌍 전체의 평균**(`np.diff`). 한 쌍만 보면 우연히 작은 쌍에 속는다
3. 🔴 **인코딩 사다리** — `q88` 시작 → **`-near_lossless 60` 을 먼저 시도**하고 한도(40,960 B) 초과 시 `q98`→아래로. 이음매를 만든 것은 생성이 아니라 인코딩이었다

**판정 기준: `비 ≤ 2.0` 단독.** 절대치는 참고로 함께 찍되 **자동 통과 사유로 쓰지 않는다.**

🔴 **이 기준의 이력을 남긴다 — 한 번 느슨하게 바꿨다가 되돌렸다.**
V6 지적 직후 인코딩을 `q98` 로 올렸더니 `metal` 세로 비가 **2.01** — 기준 2.0 에 **0.01 차로** 걸렸다. 그때 판정식을 「비 > 2.0 **이면서** 절대차 > 1.5 계조」 **AND 로 느슨하게 바꿨다.**
**그것은 기준을 결과에 맞춰 옮긴 것이었다.** DEV **PD-20** 이 금지한 바로 그 행위다 — *"합격창이 도달 불가면 합격창을 옮긴다. **값을 합격창에 맞추지 않는다**."*
이후 **인코딩 사다리를 `-near_lossless 60` 우선으로 제대로 고치자** 5종 실측 최대 비가 **1.68** 이 되어 **엄격한 단독 기준으로도 전건 통과**한다. 느슨한 기준은 **애초에 필요하지 않았다.**
→ **원래 기준으로 되돌렸다.** 여유가 **0.32** 있다.

⚠️ 한 축이 거의 균일한 텍스처는 내부 차이가 0 에 가까워 **0.3 계조 이음매가 비 5 로 뜰 수** 있다(사람 눈은 1.5 계조를 못 본다). **그런 경우가 실제로 나오면 도구가 실패로 띄우고 사람이 근거를 적어 예외 처리한다. 도구가 알아서 봐주게 두지 않는다.**

## 6-2. 🔴 2026-08-21 개정 — `metal.webp` 재생성 (TEX-R)

### 왜 고쳤나
오케스트레이터 확정 판정식(**순열검정 · MAD · α = 0.05 · p = (ge+1)/(n+1)**, 도구 `이미지/_tex_seam.py`)에서
`metal` **가로 이음매가 p = 0.0449 로 불합격**이었다(여유 0.0051). 나머지 4종 8건과 `metal` 세로는 통과.

🔴 **임계값·판정식은 손대지 않았다.** `_tex_seam.py` 는 읽기만 했고 α 도 통계량도 그대로다(D-041 ①).
고친 것은 **그림(생성식)**이다.

### 원인 — 인코딩도 `fbm` 항도 아니다. `anisotropic` 의 **x 보간 위상 비균질**이다

측정으로 먼저 분리했다(SPEC 순서 준수 실행 · 필드값을 ×28(=2×진폭14) 하면 픽셀 계조).

| 대상 | 가로 이음매 MAD(픽셀 환산) | 내부평균 | 비 | 백분위 | p |
|---|---|---|---|---|---|
| `anisotropic(384,10)` 항 단독 | **8.6927** | 5.1803 | 1.678 | 96.28 % | **0.0391** |
| `fbm([32,96],[0.6,0.4])` 항 단독 | 0.2873 | 0.7215 | 0.398 | 1.57 % | 0.9844 |
| 가중 후 `0.75 × anisotropic` | **6.5195** | 3.8852 | 1.678 | 96.28 % | **0.0391** |
| 가중 후 `0.25 × fbm` | 0.0718 | 0.1804 | 0.398 | 1.57 % | 0.9844 |
| 합성 `F` → 납품 `.webp` | **6.5352** | 3.8882 | 1.681 | 95.69 % | **0.0449** |

⇒ 이음매 6.5352 중 **6.5195(99.8 %)가 `anisotropic` 항**에서 왔다. `fbm` 항은 무죄다.
⇒ **인코딩도 무죄다.** 압축 전 6.5352 → 압축 후 6.5352 (변화 0). 하위조 SEAM 의 *"인코딩이 5.39→6.54 로 밀어 올렸다"* 는 **단독 호출 함정에 빠진 오진**이었고, TEX-R 이 SPEC 순서 준수로 재현해 **압축 전부터 불합격**임을 확인했다.

**메커니즘 (실측 근거)**
`N/freq_x = 512/384 = 4/3` → 픽셀 보간 위상 `t` 가 `0 → .75 → .5 → .25` 로 **주기 4** 순환한다.
smoothstep 증분이 `.84375 / .34375 / .34375 / .84375` 로 **한 칸 걸러 2.5배** 차이 나므로,
인접쌍 MAD 가 **4개 계층의 혼합분포**가 된다. 511개 내부쌍을 위상별로 갈라 실측한 평균(필드값):

| `j mod 4` | 개수 | 평균 MAD | 중앙 | 최대 |
|---|---|---|---|---|
| 0 | 128 | 0.244376 | 0.241593 | 0.435007 |
| 1 | 128 | 0.129358 | 0.129769 | 0.200955 |
| 2 | 128 | 0.129073 | 0.126610 | 0.206313 |
| 3 | 127 | 0.237643 | 0.235740 | 0.433188 |

이음매 쌍은 `(col511, col0)` = `j = 511`, `511 mod 4 = 3` → **고분산 계층**이다.
→ 저분산 계층까지 섞인 풀 511개 안에서 순위가 **96.28 %** 로 부풀려졌다.
→ **같은 위상 계층 127개 안에서만 재면 94.49 %** 다. 즉 **분포 혼합이 만든 순위 부풀림**이며,
   격자 자체는 `x0 = floor(idx) % freq`, `x1 = (x0+1) % freq` 로 **진짜 주기적(타일러블)**이다.

### 처방 — `anisotropic(384, 10)` → `anisotropic(256, 15)`

위상이 균질해지려면 `m = N/freq_x` 의 smoothstep 증분이 전부 같아야 하고, 그것은 **`m ∈ {1, 2}`** 일 때만 성립한다.
(실측: `m=1` → `[1.0]` ✅ · `m=2` → `[0.5, 0.5]` ✅ · `m=3` → `[.259, .481, .259]` ✗ · `m=4` → `[.156, .344, .344, .156]` ✗)
⇒ `freq_x ∈ {512, 256}`.

동시에 **난수 draw 수를 보존**해야 한다 — `rng` 는 `_tex.py` 모듈 전역이고 SPEC 이 순서대로 소비하므로,
`rng.random((fy, fx))` 가 쓰는 `fx*fy` 개 double 이 달라지면 **뒤 순서인 `slurry-pad` 가 통째로 바뀐다.**
개정 전 draw 수 = `384 × 10` = **3840**.

| 후보 | `freq_y = 3840 / freq_x` | 채택 |
|---|---|---|
| `freq_x = 512` | 7.5 — 정수 아님 | ✗ |
| `freq_x = 256` | **15** | ✅ |

⇒ 두 제약을 동시에 만족하는 해는 **`(256, 15)` 하나뿐**이다. 🔴 **p 가 큰 후보를 훑어 고른 것이 아니다**(D-041 ①).
실제로 뽑는 난수 3840개는 **개정 전과 완전히 동일**하고 격자 모양만 `(10,384) → (15,256)` 으로 바뀐다.
